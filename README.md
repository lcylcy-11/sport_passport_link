## 공개 배포 — 2026-10-03

최종 통합본: https://beanifit-dwnc.vercel.app/ . Vercel Node 24와 Supabase Auth/PostgreSQL을 사용하며, 로그인·운동·채팅 변경은 서버에 영속 저장됩니다. 기존 로컬 앱은 아래 SQLite 실행 방법을 계속 사용합니다.

선택한 브랜치의 원형 콩 아바타·영문 종목명·가로 통계 카드 형태를 홈과 친구 신분증에 적용했습니다. 시연 계정의 홈에서는 운동 10회 추가와 추가한 시연 기록 초기화 버튼으로 콩과 프로필 통계를 함께 바꿀 수 있습니다. 기존 기록·다른 사람 기록은 보존합니다.

서버 연결/배포 방법과 한계: [docs/CLOUD-SETUP.md](docs/CLOUD-SETUP.md). 검사: `npm run check`, `npm run test:cloud`, `npm run test:build`, `npm run build:cloud`. 원본 DB, 기존 디자인 초안, 별도 프로젝트는 배포에 포함하지 않습니다.

공개 허구 시연 계정: `kong@example.test` / `BeanifitDemo2026!`. 홈에서 **운동 10회 추가 → 시연 기록 초기화**로 0→10→0을 보여줍니다. 풍부한 기존 운동/채팅 데이터는 같은 비밀번호의 `minseo@example.test`로 확인하세요. 초기화는 추가한 시연 기록만 지우며 기존 기록을 보존합니다.

테니스·풋살·러닝의 공개 신분증, 콩 키우기, 함께할 사람 찾기와 운동 기록을 연결합니다. 커뮤니티 채팅에서 시간·장소를 합의하고, 운동 결과는 참가자 전원 승인 후 확정합니다. 이메일 로그인·SQLite 저장을 사용하는 로컬 MVP 전체에 라이트 글래스 톤을 적용했습니다. PC에서도 최대 390px의 같은 모바일 화면과 하단 메뉴를 중앙에 표시합니다.

## 실제 사용자 흐름

- 회원가입·로그인·홈 하단 로그아웃. 즐기는 스포츠, 사진, 지역·수준·소개 편집.
- 운동 모집 → 조건 검색 → 참여 신청 → 모집자 수락 → 기록 제안 → 확정 참가자 전원 승인 → 테니스 점수/풋살 MVP/러닝 거리·페이스 기록 확정 → 함께 참석한 상대 별점 평가.
- 홈 공개 신분증 → 180° 좌우 회전 → 콩 카드. 최근 운동/최근 2주 통합 기록, 한 줄 메모, 같은 글래스 톤의 신분증/오늘 PNG(1200×630). 스탬프 UI는 제거했으며 원래 결과는 운동 기록으로 유지합니다.
- 하단 메뉴는 **홈·매칭·랭킹·커뮤니티**입니다. 매칭에는 내 일정·일정 충돌 없는 운동 친구 추천·모든 모집 검색이 함께 있습니다. 커뮤니티는 친구/그룹/채팅 탭이며 알림은 상단에서 엽니다.
- 공개 운동 기록을 기준으로 종목·활동 지역별 랭킹을 계산합니다. 타인의 비공개 장소·운동·결과는 서버에서 제외됩니다.

다른 계정은 시크릿 창이나 다른 브라우저에서 접속하세요. 상단 새로고침으로 다른 창의 신청·수락을 가져옵니다. 서버가 로그인한 사용자를 결정하므로 브라우저에서 다른 사람으로 전환하거나 전체 데이터를 덮어쓸 수 없습니다.

## 채팅·약속·기록 합의 — T26

친구 프로필의 **채팅하기**, 수락된 운동 상세의 **매칭 채팅**, 그룹 상세의 **그룹 채팅**으로 대화를 시작합니다. 텍스트 메시지는 SQLite에 저장되며, 열린 대화에서 약 4초마다 조회합니다. 이전 메시지 조회, 초안 유지, 동일 메시지 재시도 중복 방지를 지원합니다.

**약속 잡기**에서 날짜·시간·장소·주소를 제안합니다. 그룹은 함께할 회원을 선택합니다. 선택한 참가자 전원이 승인하면 각자의 매칭 화면 내 운동 일정에 반영됩니다. 변경 제안은 새 버전으로 이전 동의를 초기화합니다. 마지막 승인 시 겹치는 일정과 지난 시작 시간을 검사합니다. 친구 약속은 해당 참가자만 볼 수 있고, 새 약속은 추가 모집을 닫습니다.

운동 뒤 한 사람이 기록을 제안하면 승인 대기로 남습니다. 원래 확정 참가자 모두가 동의할 때만 통계·콩·랭킹·공유 입력에 반영됩니다. 기록에서 불참으로 표시된 사람도 승인해야 합니다. 기존의 혼자 참석한 러닝·인원 부족 테니스 미성립 기록은 실제 확정 명단이 한 명인 경우 그대로 지원합니다. 확정 이후 함께 참석한 상대에게 1~5점 별점을 명시적으로 제출하며, 공개 프로필은 실제 평균과 평가 건수를 다섯 별로 표시합니다.

장소·주소의 **지도 열기**는 Google Maps 검색 링크입니다. 위치 권한, 앱 내부 지도 SDK, 좌표·반경 매칭은 추가하지 않았습니다. 팀원의 SNS 카드에는 [확정 기록 데이터 계약 v1](docs/workout-share-contract.md)의 `workout-share-data.js` 어댑터를 연결하세요. 승인 대기 기록과 타인의 메시지·평가 원문은 카드 입력에 포함되지 않습니다. 기존 `cards.js`와 팀원 브랜치는 수정하지 않았습니다.

## 신분증과 콩, 통합 화면 — 2026-10-03, T24

- 홈 기본 앞면은 공개용 신분증입니다. 실제 닉네임·사진·성별·나이/연령대·지역·소개·종목별 구력과 수준을 표시합니다. 카드 위 버튼으로 좌우 180° 회전하며 개인용 콩 카드로 전환합니다. 다른 사람 프로필도 항상 신분증부터 열리고 버튼으로 콩과 기록을 볼 수 있습니다. 편집·사진·종목·공유 PNG·로그아웃은 홈에 있습니다.
- 최근 운동 한 카드에서 최근 14일 빈도와 그 기간의 최신 5개 실제 기록을 봅니다. 홈의 전체 기록 버튼과 매칭의 최근 기록 버튼은 같은 참석 결과 목록을 엽니다. 상세 → 결과 저장 → 홈 콩 카드로 연결합니다. 과거 스탬프 UI/획득 알림/공유 도장은 제거했으며 원본 DB 결과는 그대로 사용합니다.
- 저장된 결과에 본인 참석이 확인된 운동만 matchId별 1회 집계합니다. 대기·취소·불참·타인 결과·미래 날짜는 제외하며 날짜와 일정 종료 판정은 한국 시간(Asia/Seoul) 기준입니다. 캐릭터 상태 추가 저장이나 DB 스키마 변경은 없습니다.
- 성장 1/5/15/30/50/100회, 종목별 아이템 1/10/25/50회, 휴식 컨디션과 미성립 테니스 참석 집계는 **KONG_PREVIEW_POLICY** 예시값입니다. 성장 곡선은 없습니다. 휴식은 성장·아이템을 감소시키지 않습니다. 0회는 정지 아기 콩과 첫 기록 안내입니다.
- 실제 새 참석 결과가 성공적으로 저장되면 홈 콩 카드가 한 번 반응합니다. 실패·409·이미 반영된 결과에는 가상 횟수나 보상이 없습니다. 회전 중 반응 취소 시 idle로 복원하고 화면/계정 변경 시 타이머를 취소합니다. 비활성 카드 면은 inert/aria-hidden으로 키보드·접근성에서 제외합니다. 동작 줄이기는 회전/SMIL을 줄이거나 없앱니다.
- 매칭 추천은 즐기는 종목·지역·공개 범위·신청 가능 조건을 만족하고, 확정된 모든 종목 일정과 시간이 겹치지 않는 모집입니다. 같은 날/가까운 시간 순으로 이유와 모집자 신분증 링크를 표시합니다. 오늘 종료 시각이 지난 무기록 일정은 기록 대기 목록으로 이동합니다.
- 지역 랭킹은 **공개 운동만**으로 승률 50점 + 직접 입력한 구력 20점(최대 10년) + 같은 종목 최근 14일 운동 30점(최대 6회)을 계산합니다. 해석할 수 없는 구력·경기 없음은 해당 점수 0, 러닝은 승률 미적용(최대 50점)입니다. 모든 이용자에게 동일한 공개 기록 기준을 적용하고 비공개 기록은 본인 기록과 콩 성장에 계속 반영합니다. 계산 비중은 검토용 정책이며 화면에서 설명합니다.
- 이전 profile/activity/people/groups 링크는 각각 홈/매칭/커뮤니티 친구·그룹 화면으로 연결됩니다. 서버 알림과 이전 공유 링크도 유지합니다.

기존 4174 서버가 실행 중이었다면 수정된 정적 파일 allowlist를 적용하도록 해당 서버의 실행 터미널에서 정상 종료 후 `npm start`로 다시 시작하세요. 기존 `data/dwnc.sqlite`를 초기화하거나 시드를 실행할 필요가 없습니다. 원본 시안·기존 DB를 보존하며 `submit-before/`를 다루지 않습니다. T25에서는 사용자의 명시적 요청으로 완료된 앱을 기존 정본 브랜치에 커밋·푸시합니다. 배포는 별도 승인 사항입니다.

## DB · 인증 · 설정

기존 스택은 브라우저 ES 모듈 + Node HTTP 서버입니다. Better Auth **1.7.7**가 비밀번호 해시와 서버 세션을 담당하고, Node SQLite가 계정과 운동 데이터를 영속 저장합니다. Zod가 서버 입력을 검사합니다. Auth 데이터와 도메인 테이블은 하나의 로컬 DB에 있으며, 외래 키·트랜잭션·리비전 충돌·요청 ID 재사용 검사를 적용합니다.

```powershell
npm run db:migrate
# 선택 사항: 빈 로컬 DB에 허구 운동 예시만 넣습니다.
npm run db:seed
```

기본 `data/dwnc.sqlite`는 시작 시 자동으로 생성·마이그레이션됩니다. 시드는 기존 데이터가 있으면 거부합니다. 예시 프로필에는 로그인 계정이 없으므로 실제 계정 흐름은 직접 가입하여 시연합니다.

`.env.example`은 값 없는 템플릿입니다. `.env`가 없거나 값이 비면 로컬 기본 설정으로 실행합니다.

| 변수 | 용도 / 로컬 기본값 |
|---|---|
| `PORT` | 로컬 포트, 4174 |
| `DATABASE_PATH` | SQLite 파일, `data/dwnc.sqlite` |
| `BETTER_AUTH_URL` | 정확한 사이트 Origin, `http://127.0.0.1:4174` |
| `BETTER_AUTH_SECRET` | 선택적 로컬 인증 비밀값. 미설정 시 파일에 쓰지 않는 프로세스 전용 값 |
| `NODE_ENV` | 기본 개발 모드. production은 HTTPS와 32자 이상 비밀값 없으면 거부 |

기본 개발 모드에서는 서버 재시작 후 다시 로그인해야 합니다. 계정·운동 기록은 유지됩니다. `localhost`와 `127.0.0.1`을 섞지 마세요. 포트를 바꾸면 URL도 같은 포트로 지정하세요. 비밀값·DB를 Git에 넣지 마세요.

## API

| 경로 | 역할 |
|---|---|
| `/api/auth/sign-up/email`, `/sign-in/email`, `/sign-out`, `/get-session` (모두 `/api/auth` 아래) | Better Auth 가입·로그인·로그아웃·세션 |
| `GET /api/state` | 인증 사용자에게 허용되는 화면 데이터, 리비전 |
| `POST /api/commands` | 검증된 프로필/운동/친구/그룹/알림 작업 |
| `GET /api/chats`, `POST /api/chats/open` | 현재 접근 가능한 대화 목록·친구/매칭/그룹 방 열기 |
| `GET/POST /api/chats/:roomId/messages` | cursor 메시지 조회·중복 방지 텍스트 전송 |
| `GET /api/health` | 로컬 DB 연결 확인 |

명령 본문은 `{type, payload, revision, requestId, expectedUserId}`입니다. 예: `note.save`, `match.create`, `match.apply`, `match.decide`, `result.save`. 작업마다 허용 필드를 검사하고, 사용자 ID는 세션에서 가져옵니다. `expectedUserId`는 다른 탭에서 계정이 바뀌었는지 검사하는 값이며 권한을 부여하지 않습니다. 변경 요청은 사이트와 같은 `Origin`의 JSON 요청이어야 합니다. 리비전 충돌은 409로 반환합니다. 네트워크 재시도는 동일 요청 ID로 중복 생성을 막습니다.

약속 명령은 `appointment.propose/decide`, 기록 명령은 `result.propose/decide`입니다. 기존 `result.save`도 제안으로 처리합니다. 승인·거절은 `{proposalId,version,decision}`을 전송하며, 변경된 버전의 승인은 거부합니다. 채팅 메시지는 독립 저장되어 운동 명령의 리비전을 변경하지 않습니다. 시작 시 기존 001 다음에 002 협업 마이그레이션을 순차 적용하며 과거 확정 기록을 재승인 상태로 바꾸지 않습니다.

## 현재 노트북 실행 환경 — 2026-10-03

이 노트북의 `.env`는 **http://127.0.0.1:4194/#/home**을 사용합니다. 기존 4174 서버와 충돌하지 않도록 포트와 인증 URL을 함께 변경했습니다. `npm start`는 이 설정을 자동으로 읽습니다. 원래 Node 24.19.0/npm 11.17.0 설치 경로를 사용자 PATH에 등록했습니다.

새 터미널에서 실행하세요. 기존 터미널은 먼저 PATH를 갱신합니다. PowerShell 실행 정책의 영향을 피하도록 `npm.cmd`를 사용합니다.


이미 4194 서버가 실행 중이면 중복 실행하지 마세요. 이번 설정에서 실행한 백그라운드 서버의 PID와 로그는 `.runtime/laptop/server.pid`, `server-4194.stdout.log`, `server-4194.stderr.log`에 있습니다. 기능 수정으로 서버 재시작이 필요하면 해당 프로세스가 이 프로젝트의 DWNC 서버인지 확인하고 종료한 뒤 위 명령으로 실행하세요. 다른 작업의 4174 서버는 보존했습니다.

사용 중인 DB는 **`%LOCALAPPDATA%/DWNC/sport-passport/dwnc.sqlite`**입니다. 프로젝트가 있는 OneDrive 동기화 폴더 밖에서 노트북이 독립적으로 저장합니다. 원래 `data/dwnc.sqlite`는 이전 자료로 보존했으며, SQLite 백업 API로 기존 WAL까지 포함한 일관된 복사본을 만들어 계정을 유지했습니다. 현재 DB의 이전 직전 및 검증 후 백업은 같은 위치의 `backups/` 폴더에 있습니다. 앞으로 원래 `data/`와 현재 DB는 자동 동기화되지 않습니다. 앱은 `.env`의 `DATABASE_PATH`를 기준으로 작업합니다.
